# shbox CLI / configuration simplification — rolling execution plan

## User value and current contract

Operators configure shbox with one small TOML file containing only persistent
policy (`authorized_keys`, `admin_keys`, `sandbox_shell`, `read_paths`, and
`sandbox_env`). Process-lifetime choices are command-line options, and resource
limits are built-in safety defaults.

```console
shbox --listen 127.0.0.1:2222 --network outbound --log-level debug --authorized-keys-host-access
shbox --completions zsh
shbox --man > shbox.1
```

A config file containing `listen`, `network`, `log_level`, `limits`, or `caps`
is rejected as an unknown field. Completion scripts and the man page are
generated in-process from the same `usage-rs` CLI declaration as `--help`.

## Current state

- M1–M6 are implemented in the current working tree. The CLI output actions,
  operational CLI options, fixed resource defaults, host-access authorization,
  file-backed SIGHUP reload, integration fixtures, documentation, and service
  examples are all updated together.
- `Config` and `RawConfig` contain only file-backed policy. `Caps` and `Limits`
  remain domain types for the platform boundary, but their values come only
  from `Default` and cannot be loaded or replaced from TOML or SIGHUP.
- `--listen`, `--network`, `--log-level`, and
  `--authorized-keys-host-access` are parsed before daemon bootstrap. The first
  three remain fixed for the process lifetime; the host-access flag is also
  fixed and promotes every authorized key to `Admin` when enabled.
- SIGHUP validates and publishes only the file-backed configuration and auth
  snapshot. Existing connections retain their role snapshot; new connections
  see the new file-backed policy.

## Decisions and discoveries

- Output actions are emitted in `main()` before the tokio runtime exists, so
  `--completions` and `--man` cannot touch config, keys, sockets, or logging.
- Unsupported completion shells are `ValueEnum` parse errors (non-zero exit);
  the accepted set is exactly bash, zsh, fish, and powershell.
- Process-lifetime options are intentionally not reloadable. A SIGHUP that
  contains a retired TOML field fails atomically rather than silently changing
  the running daemon.
- `--authorized-keys-host-access` grants daemon-user host authority by design;
  it is documented as a deployment-level trust decision.
- The completion scripts generated by `usage-rs` invoke the shbox binary for
  dynamic completion; no external `usage` executable is needed.
- Linux-only cgroup behavior cannot be exercised on this macOS host. The
  native Linux gate remains an explicit CI responsibility.
- Rollback is an ordinary `git revert` of the implementation commit; no
  external state is modified by the configuration migration.

## Risks and constraints

- Moving settings out of TOML is a deliberate compatibility break. Operators
  must move listener, network, and log-level values into service command-line
  arguments; old keys fail closed with `unknown field`.
- Deployment examples must keep passing explicit CLI defaults so systemd and
  launchd behavior remains equivalent after the schema change.
- The macOS platform gate warns that Apple has deprecated Seatbelt; the pinned
  Arapuca backend still requires `/usr/bin/sandbox-exec`.
